Run a shell command in the workspace and wait for it to finish before the next step. Use trigger instead of run_command when the command's length is the point — a build, a test suite, a training run, a long download: run_command's budget is about 30 seconds and a command that outlives it is killed, while trigger waits up to six hours. Nothing happens in the loop while it runs, so no tokens are spent waiting and there is no reason to poll. The tool result is the command's output, and a non-zero exit is reported with its exit code so you can read what went wrong. Stop still cancels it. cwd is fixed to the workspace root; run Python with `python3 file.py`; interactive commands (bare python, vi, vim, less) are blocked.
